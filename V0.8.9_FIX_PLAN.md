# LP Manager v0.8.9 bug-fix checkpoint

Branch created from the green v0.8.8 release head `e15e36e392cdff5eb9a92787adf4ec222001eeb6`.

## User-reported failures to close before capital deployment

1. Profit Lab must not fail on rapid refresh / GeckoTerminal 429s. Use deterministic provider priority, deduplication, persisted stale-while-refresh history, and independent on-chain price-history fallback where possible.
2. Remove the duplicate/slow "Find best across chains" workflow from Profit Lab. Portfolio Advisor owns cross-chain capital allocation; Profit Lab owns one selected pool/tier/range.
3. Closed LPs must be reconstructed once from their lifecycle (opening, fee collections, liquidity removal/close, gas), final P/L stored as immutable JSON, and no longer rescanned for live range management. Closed cards should not show range bars or live APR.
4. Wallet chooser must actually prompt the selected wallet to connect. Providers remain deduplicated; add a proper Phantom visual fallback.
5. Performance layout must render four readable cards. All-time fees must expose an auditable per-position breakdown and avoid double counting.
6. Portfolio Advisor and Profit Lab must use the same canonical pool/economic evidence. A pool ranked as profitable by Advisor must not become a zero-fee Profit Lab result unless the evidence is explicitly invalidated; insufficient evidence must be labelled, not silently converted to £0.
7. Reduce redundant overview/target refresh calls so normal UI use does not amplify provider pressure.
8. Keep browser-wallet explicit approval as the signing boundary. Do not introduce autonomous signing in this bug-fix release.

## Release gate

Before packaging: Python 3.12 + 3.13 CI green, browser JS syntax check green, dedicated regression tests for the failures above, and packaged ZIP contains no user secrets/runtime DB.
